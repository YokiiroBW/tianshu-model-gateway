# TS-041：首轮诊断持久化

2026-09-14。本切片选 Python 标准库 SQLite，单进程、本地文件，WAL 与短事务；路径必须由部署方指定。测试全部使用临时目录。它让首轮真实 HTTP 入口具备可重启核对的诊断，避免为尚未接入的平台引入第二个数据库服务或旧控制平面。

保存：(authenticated_service, request_id) 唯一路由回执、脱敏内部结果原因/耗时/HTTP 状态、轮次固定版本、已知撤销版本、同版快照内容摘要。上游发送前先写 unknown；终态写入失败或进程崩溃时保留 unknown，不自动重放。正文、Key、凭据引用、原始异常和模型内容不持久化。原生成功响应直接给调用方，查询接口只返回独立回执。

SQLite 只证明本地隔离运行和重启；不是 PostgreSQL 兼容承诺。生产 PostgreSQL 适配、迁移版本、跨进程原子性/连接池、备份恢复、容量/清理策略与高可用未实现未验证。当前并发配额也仅在一个网关进程内计数，不能多开进程绕过配额。发布生产数据库方案前，应复验“发送前可靠记账、相同 ID 不重放、同轮不换版、失联为 unknown、查询按服务隔离”和故障恢复，并明确留存期限。

本地回滚：停服务，保留该任务的隔离诊断文件供核对，切回前一个已审查提交；不要把旧记录移入真实生产库或删除 unknown 后重放。配置缓存仅在内存中，重启平台不可用时会拒绝首次调用。测试服务与命令行子进程结束后都停止，不留后台生产守护程序。
