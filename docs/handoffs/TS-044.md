### 1.2 调用端口与状态所有者

| 端口 | 输入（已核验） | 输出 | 状态所有者 |
| --- | --- | --- | --- |
| `BoundedAdmissionScheduler.acquire(service, workload_class, declared_workload, key, provider_id, timeout_ms)` | 已认证主体、部署绑定类别、启动键、**已由固定版本配置选定的 provider**、期限 | `Waiter` 或领域异常 | 调度 |
| `BoundedAdmissionScheduler.release(waiter)` | 已取得的 permit | 无（幂等，唯一权威释放路径） | 调度 |
| `scheduler.bind(...)` 适配器（`_Permit`） | 每次尝试的 permit 生命周期 | `__aenter__` / `live()` / `__aexit__`（守卫式 `release`） | 调度（适配层） |
| 领域异常 `AdmissionRefused` / `QueueFull`(429) / `DuplicateRequest`(400) | 固定原因串 + HTTP 状态 | server 适配为 `Rejected` | 调度定义、server 映射 |
| 诊断端口（可选注入） | 有界事实 `record_admission(service, request_id, workload_class, outcome, wait_ms)` | 无返回值；失败只降级为一条无值告警 | 诊断模块 |
| 时钟 | 构造注入（默认 `time.monotonic`） | 单调时间 | 测试可替换 |

provider 只作为 `acquire` 的一个**输入**传入：队列里没有"稍后再选 provider"的阶段，因此等待不可能把请求改投到别的 provider。

### 1.4 依赖方向与共享入口修改

```
server.py（协议入口/组合根适配）
```

## 2. 实际变更

- **新增** `src/tianshu_gateway/scheduler.py`：单进程内存有界准入调度。公开端口 `acquire/release/bind`、领域异常、观测结果常量；只依赖标准库。
  - 容量模型：全局硬上限与每 provider 硬上限独立判定，两个门都满足才发放 permit。
  - 保留容量：后台最多持 `max_in_flight - interactive_reserve`（全局）与 `max_provider_in_flight - interactive_reserve`（每 provider）个槽位，用后台**自身**的账本计数（`_background_active` / `_background_provider_active`）衡量，而不是用总负载——这是本轮修正的一个真实缺陷（用总负载衡量会使后台在交互占满池时连自己的额度也用不到）。
  - 等待：同类 FIFO、交互等待者永远先于后台被考虑；`asyncio.wait_for(asyncio.shield(...))` 实现期限；期限/取消都先出队再放弃。
  - 单遍 `_pump_locked`：一次遍历同时尝试两个类别，避免"已批准但尚未挂接 provider 门"造成的死锁。
- **修改** `config.py`：`SchedulingPolicy`（含 `validate()` 与 `default_policy`）与 `Classification`（`for_service`）。
- **修改** `server.py`：设置字段与校验、`Gateway.scheduler/pool_active/class_for/declared_workload/slot`、`_CounterSlot`（旧语义）、两条路由的准入接线与发送前重验、组合根装配、连接器上限改为 `max(max_concurrent, max_in_flight) + 1`（等待不占用上游连接）。
- **修改** `diagnostics.py`：`admission_metrics` 表 + 迁移编号 2 + `record_admission`/`admission`。
- **修改** `tests/gateway_fixtures.py`：并发挂起与按尝试放行（保留 `release`/`native_release` 单次挂起语义）。
- **修改** `tests/test_usage_report.py`：迁移断言跟事实更新。
- **新增** `tests/test_ts044_scheduling.py`（41 例）：策略校验、调度核心、旧语义保持、真实网关 + 录制上游场景。
- **文档** `docs/gateway-runtime.md` 新增「TS-044 有界调度运行边界」节。

### 与设计稿的偏差（已收敛，记录在案）

- 早期设计有 `acquire` + `reserve(provider_id)` 两阶段；实现收敛为 `acquire(..., provider_id, ...)` 单输入，因为两阶段会让"已批准但未挂接 provider 门"的等待者无法被唤醒（真实死锁，已复现并修正）。
- 后台公平性的度量从"总 provider 负载"改为"后台自身账本"，理由见上。

### 本轮修掉的两个真实回归（不属于本卡新增行为，但由本卡改动引出）

1. 请求体读取超时：把"解析先于容量"的重排后，`TimeoutError` 落到中间件的兜底分支变成 503。现在两条路由的读取都用 `except TimeoutError: raise Rejected("timeout", 408)` 显式翻译，恢复 `test_gateway_http` 的 408 期望。
2. 录制上游只支持单个共享挂起事件，导致同一调用方的并发尝试互相阻塞（表现为大面积 502）。改为每次尝试独立事件，并让 `release`/`native_release` 继续有效，恢复 `test_usage_report` 的 `test_a_duplicate_concurrent_request_is_counted_once`。
