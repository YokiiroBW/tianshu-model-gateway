# TS-137 — 同来源授权瞬时续租失败恢复

## 目标与基线

修复已确认授权的续租遇到一次整轮瞬时失败后永久关闭的问题。分支 `codex/gateway-origin-recovery-20261014`；精确部署基线 `f57d38e19416b7fa1a956e9557024fe1e1b75c4b`。本候选提交以该分支最新提交为准，只有本地开发、验证与提交；集成、推送、部署及 NAS 验收由父级协调者完成。

改动仅在 `src/tianshu_gateway/origin_renewal.py`、两个既有 origin renewal 测试模块与本文。父级补充授权在 `tests/test_origin_renewal_joint.py` 增加真实两产品 TLS 回归；未改公共合同、依赖、设置或其他产品实现。

## 变更与复用

- 复用 `SourceUnavailable` 的明确传输/服务故障分类，以及原有每轮三次尝试、三秒整轮 deadline、同 ref 请求与 single-flight。没有按照所有 503 归类瞬时故障。
- 已确认且未过期的同来源遇到连接故障、整轮超时、5xx 或 429 后，保留原期限作为重试上限，轮间退避从 0.25 秒递增至最多 2 秒。后台 worker 继续与业务 `ensure()` 共用 flight 和退避；关闭可以立即取消等待。
- 首次瞬时失败即标记暂时不可用。`check()` 不发请求、不更新授权期限；故障期间 `CurrentCache` / `CurrentSource` 仍拒绝配置访问，向调用方抛普通 `Rejected(503)`，不暴露允许缓存回退的 `SourceUnavailable`。
- 只有合法同 ref、同请求回声的 200 才提交新期限，并清除暂时失败。提交前重新检查原 wall expiry、monotonic deadline、同 ref 环境输入、关闭及硬拒绝状态，同时复核三秒整轮截止时间。
- 401/403/410、撤销、环境 ref 替换、过期、非法 JSON/回声/编码/期限以及首次 bootstrap 失败继续终止。没有 issue 新 ref、凭据、权限或自动重放模型业务。
