## 协调验收与返修（P1）

协调方只读验收用只对该表 INSERT 抛 ABORT 的 TEMP 触发器隔离复现了四类后果，全部由"新增私有度量写入与权威终态回执耦合在同一事务、并从转发 finally 外抛异常"引起：

| 复现场景 | 第一版实测 | 本版实测（协调探针原样重跑，见下） |
| --- | --- | --- |
| Chat JSON 上游成功 + 度量写入失败 | 503 `result_unknown`，回执 unknown | **200**，正文为上游 bytes，回执 `succeeded`/`completed` |
| Responses JSON 同上 | 502 `result_unknown`，`native_requests.reason` 停在 `in_flight` | **200**，正文为上游 bytes，reason `response_completed` |
| Chat SSE 同上 | 已 200，客户端 `read()` 抛 `ClientPayloadError` | **200**，读到完整 528 字节流，无异常 |
| 录制上游 `usage.prompt_tokens=2**63`（无故障注入） | SQLite 整数绑定溢出，成功响应变 503，回执 unknown | **200**，响应与回执保留 `9223372036854775808`，私有行不索引该值 |

修复内容：

1. **解耦**（`diagnostics.py`）：`finish()`/`native_finish()` 先用独立事务写权威回执 UPDATE（失败仍上抛，语义不变），再用 `project_metric()` 在第二个独立事务里尽力而为地写私有度量；任何度量写入失败只记一条不含值的 `metric_write_degraded table=...` 告警，不重试、不回滚回执、不改变 `reason`、不影响已交付字节。取消是 `BaseException`，仍然正常传播。
2. **投影不抛异常**：`attempt_metrics()` 改为总函数，意外一律退化为 `UNOBSERVED`（`usage_source=unobserved`）。
3. **整数范围与降级**：私有投影只索引 `0..MAX_METRIC_TOKENS`（10^15）的归一化 token 数；超范围的值不索引、不截断、不补 0，该行 `usage_complete` 记 0（投影不完整），权威回执与原生转发字段保持不变。
4. **有界聚合不溢出**（`usage.py`）：窗口求和逐行 `MIN(col, bound)` 并对超上限行给出 `clamped` 计数；新增 `normalized.*.clamped` 字段与两条 `notes`，明确"没有私有行的尝试只计入 `coverage.unmetered_total`，绝不报成 0 用量或 0 延迟"。
5. **测试边界重写**：删除原先断言"metrics 失败必须回滚回执"的组件用例（那正是缺陷本身），改为断言回执/响应不受影响、attempt 变为 unmetered。

## 发现并修复的缺陷

1. **（第一版发现）native 度量 INSERT 占位符与列数不符**：12 个占位符写 13 列（漏 `credential_namespace`），每次 native 度量写入抛 `sqlite3.OperationalError`，在 `send_responses()` 的 finally 中抛出，使回执停在 `in_flight` 并把已交付的原生响应改判为 502。已由显式列名修复并由组件 + HTTP 用例锁住。
2. **（本轮 P1，协调复现）新增诊断写入破坏主转发链**：私有度量写入与权威终态回执同事务、异常从转发 finally 外抛；且 SQLite 整数范围未处理。已按上文解耦与降级修复。修复后协调探针四条反例全部转为正确行为，130 项测试通过。
