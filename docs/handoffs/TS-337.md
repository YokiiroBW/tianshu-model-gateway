## 变化与复用

`create_app(settings, observability=None, *, internal_clients=None, environ=None, storage_options=None)` 直接复用原应用、授权、调度、账本、诊断和流式处理。没有新增第二套 Gateway 或请求协议。

显式内部交换对象只为 Platform 来源建立一次 session。Chat/native 配置、来源续期、动态模型配置和 Memory retrieval 配置走此 session；模型供应商继续使用原有 `aiohttp.ClientSession`、注册地址、TLS、连接池及 provider adapter。没有按 URL 猜目标、网络 fallback 或全局 HTTP monkeypatch。默认不注入时原网络路径保留。

EnvSecrets、两种配置来源、来源续期及 Observability 支持独立 `environ` 映射；默认仍用 `os.environ`。凭据和诊断 token 可在所属映射内轮换；来源 assertion_ref 仍不能被静默替换。宿主需显式构造 `Observability(..., environ=module_environ)`。日志实例归所属 Gateway，未改写进程环境。

统一 `tianshu-storage` 到四产品已用的 0.1.3。wheel 来自已集成 Memory 的相同制品，SHA256 `a87947a1260fd24de5ae241f19fcc3bb2c2d3fa2869c9a0328825b5f81789d0f`；0.1.0 与 0.1.3 的全部 Requires-Dist 完全相同。仅改 uv.lock 的该包版本、路径及制品 hash，未重新解析其他依赖。

## 生命周期与未覆盖

Gateway 没有新业务生产者；来源续期在原 cleanup 中关闭。宿主先停止外部根请求并排空已接收根任务，在其他模块的 producer/owned-worker drain 完成期间保持 Gateway 与 Platform 来源可达，最后才关闭交换层及账本。不能用收到 HTTP 超时推断模型或同步工作已完成。

本号尚未验证五产品同宿主、模块独立 loop、OneBot、Linux 镜像、PG/Redis、真实模型或生产升级。Memory 前台查询与后台索引目前仍共享 retrieval 容量；未擅自增加用户可伪造的优先级 header，也未宣称该预算隔离已经完成。
