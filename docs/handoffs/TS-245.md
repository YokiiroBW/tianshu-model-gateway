# TS-245 Gateway 导入摘要排序修复

基线 `d7336e013e0b194ed87717af5c288be89c18db41`；独立分支 `codex/ts-245-pg-digest`。本交接与实现同一提交，完整提交 SHA 随交付发送给协调者。本卡只做本地开发和合成验证，生产接续由 TS-244 协调者执行。

## 问题与修改

协调者的隔离事务诊断确认，SQLite 与 PG 的 `turns` 完整编码行多重集一致，但按文本主键排序的行顺序不同。原 `row_digest` 按查询返回顺序累积 SHA256，因数据库 collation 差异将完整导入误判为内容不一致。

`ledger_storage.row_digest` 保留原有完整行 JSON 编码及 `(count, digest)` 返回接口，先计算每行 SHA256，再排序这些固定长度摘要并累积总摘要。重复行保留全部次数；数值、文本、NULL 和字段内容继续严格比较。原生 DDL、导入事务、来源指纹、owner 锁和恢复逻辑保持原实现。比较临时保存每行一个摘要，内存随行数线性增加，不保存完整行正文。

新增 `tests/test_ledger_digest.py` 的四类测试：

- 实际 SQLite BINARY/NOCASE 排序和逆序产生不同顺序，完整行摘要一致。
- 相同行数下修改正文、数值或值类型，摘要不同。
- 同行数的重复次数互换，以及增删重复行，均被识别。
- 空输入稳定返回零行摘要。
